# الجزء الأول — القرار المعماري (ولماذا)

## ١) المعمارية المختارة: Feature-First + Riverpod + Offline-First

| طبقة | الاختيار | لماذا هذا تحديدًا (قياسًا على منتجنا لا عمومًا) |
|---|---|---|
| **إدارة الحالة** | Riverpod 2 (مع code-gen) | تطبيقنا «حالة عائلة واحدة» تتفرع لعشرات الشاشات (S في النموذج) — Riverpod يعطينا نفس النموذج: مزودات مشتقة، وإعادة بناء دقيقة، واختبارية بلا سياق. BLoC أثقل مراسمًا لفريق صغير، وGetX مرفوض حوكميًا (سحر خفي) |
| **بنية المجلدات** | Feature-First (features/<نظام>/) | أنظمتنا الـ٥٤ هي وحدات العمل الطبيعية — كل نظام مختوم في 31A يصبح مجلد feature بنفس الاسم والرقم، فيبقى التتبع «نظام←كود» حرفيًا |
| **قاعدة البيانات المحلية** | Drift (SQLite) | Offline-first مبدأ معتمد (باب ٩ في 40)؛ لدينا schema.sql جاهز في _CONTRACTS — Drift يحوله مباشرة بأنواع مضمونة، وواجهات Stream تعكس «آخر حالة عائلة متزامنة» |
| **المزامنة** | طابور عمليات محلي + دمج بالخادم لاحقًا | v-كود أولى بلا خادم حقيقي (mock repos) — لكن **واجهة Repository تُكتب من اليوم الأول** بحيث يُستبدل Mock بـ API بلا لمس الواجهات |
| **التنقل** | go_router (typed routes) | ١٢٩ شاشة تحتاج جدول توجيه مُولّدًا من screens.csv — ولدينا حالات حراسة أدوار (ق-٥) تنفذ كـ redirect |
| **النماذج** | freezed + json_serializable | ثبات (immutability) يمنع «تحوير الحالة خلسة» — وهو حرفيًا قانوننا: القنوات الخمس لا تُمس إلا عبر أفعال معلنة |
| **i18n** | flutter_localizations + ARB من السطر الأول (ث-٢/ع-٦) | **قانون**: لا نص عربي حرفي داخل Widget أبدًا — كله مفاتيح ARB، العربية أولى واتجاه RTL افتراضي، والإنجليزية هيكل فارغ يُملأ لاحقًا |
| **الوصولية** | Semantics إلزامي (ع-٦) | كل زر/بطاقة لها semanticLabel — قانون فحص آلي |
| **تطبيق واحد أم اثنان؟** | **تطبيق واحد بدور** (قرار مجمد سابق: نموذج التطبيقين ملغى) | تجربة الابن child-ui نفس الكود بثيم ودور مختلفين — كما في النموذج |

# الجزء الثاني — دستور كرسر (يوضع حرفيًا في `.cursor/rules/constitution.mdc`)

> **هذه القوانين مطلقة. أي مخالفة = رفض المهمة وإعادتها.**

## ق-ك١ · المرجعية والحدود
1. المصدر الوحيد للحقيقة: `family_os_app.html` (المجمد v1.0) + `40_POLICY_REGISTER_FOR_FLUTTER.md` + `_REGISTRY/screens.csv` + `_CONTRACTS/schema.sql`. **يُمنع الاجتهاد التصميمي**: أي شاشة تُنقل كما هي نصًا وترتيبًا وسلوكًا.
2. عند غموض أو تعارض: **توقف واسأل** — لا تخمن. اكتب سؤالك في `QUESTIONS.md` وأوقف المهمة.
3. يُمنع توليد شاشات أو مزايا غير موجودة في السجل (129 شاشة فقط). يُمنع إحياء الملغيات: OTP، التصميم الأخضر v1، نموذج التطبيقين، شاشة اختيار الدور.

## ق-ك٢ · دستور الاقتصاد (الأعلى قداسة — الباب ١ من 40)
4. العملة الوحيدة **دقائق**. النوع `Minutes` (value object) إلزامي — **يُمنع** `int` خام لأي مكافأة/رصيد/طلب. لا «نقاط» ولا «عملات» ولا XP في أي نص أو متغير أو تعليق.
5. قنوات الكسب الخمس (مهام، قرآن، تعلم، تحديات، هدايا) تمر حصرًا عبر `PolicyEngine.earn()` — يُمنع أي كتابة مباشرة على الرصيد.
6. الأب يحدد قيمة المكافأة عند إنشاء المهمة — لا قيم افتراضية مخفية.

## ق-ك٣ · دستور السيادة والأمان
7. كل ذكاء **يقترح ولا ينفذ** — أي فعل ذكي ينتهي بزر اعتماد والدي.
8. حراسة الأدوار عبر `RoleGuard` في الراوتر حصرًا (لا شروط if متناثرة). شاشات المالك: الاشتراك/الفوترة/الخصوصية/التدقيق.
9. زر النجدة والموقع ومحادثة العائلة: **لا يعتمدون على الاشتراك ولا يُعطَّلون أبدًا** — أي كود يشترط باقة عليهم مرفوض.
10. سجل التدقيق append-only: واجهة الـ repo لا تحتوي update/delete أصلًا.
11. انتهاء الوقت لا يقفل أبدًا: محادثة العائلة، القرآن، النجدة.

## ق-ك٤ · دستور الكود
12. لا نص معروض حرفيًا في Widgets — **كل النصوص من ARB**. فحص `check_hardcoded_ar.dart` يرفض الـ PR.
13. لا أسماء أبناء حرفية خارج `mock/` — كل شاشة ابن دالة في `ChildId`.
14. الألوان والظلال والزوايا من `tokens.dart` فقط — يُمنع `Color(0x…)` داخل features.
15. كل مكوّن مرئي جديد يُضاف في `core/design/components/` مرة واحدة — يُمنع تكرار زر/بطاقة محليًا.
16. `Semantics` label لكل عنصر تفاعلي. أهداف اللمس ≥ 48dp.
17. كل fetaure يشحن مع: اختبار وحدة للمنطق + اختبار Widget يثبت (أ) العرض (ب) **كل زر له فعل** (ج) إغلاق الحلقة (توست/تغير حالة/تنقل).
18. الالتزام الصارم بـ `flutter analyze` صفر تحذيرات + `dart format` قبل أي commit.

## ق-ك٥ · دستور سير العمل مع كرسر
19. **مهمة واحدة = نظام واحد (أو شاشة واحدة)** — يُمنع «حوّل عشر شاشات دفعة». كل مهمة تستلم: رقم النظام، قائمة شاشاته، مقتطف HTML الأصلي، بنود 40 ذات الصلة.
20. كل مهمة تنتهي بـ: كود + اختبارات خضراء + سطر في `CONVERSION_LOG.md` (رقم الشاشة، الالتزامات، أي انحراف مُعلن).
21. يُمنع على كرسر تعديل: `core/policy/` و`tokens.dart` و`.cursor/rules/` — تغييرها قرار مالك مسجل فقط.
22. أي commit يمس أكثر من feature واحد يُرفض (عدا core بمهمة معلنة).
