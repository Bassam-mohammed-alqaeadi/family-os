## أ) القوانين السبعة للورشة (ملزمة في كل محطة)
1. **لا اختراع**: كل جملة في التوثيق تُشتق من وثيقة مصدر موجودة (تُذكر في رأس كل محطة). عند غياب مصدر → سؤال للمالك، لا تأليف.
2. **الأرقام الحاكمة**: 240 خدمة / 73 رحلة / 129 شاشة / 5 أدوار / 20 جدول قاعدة بيانات — أي رقم يُذكر يطابق `_REGISTRY` وschema.sql حرفيًا، ويُفحص آليًا (قانون ٧).
3. **النسق الحرفي للمرجع**: نفس ترقيم الفصول والعناوين، نفس أسلوب جداول «الحقل/الوصف»، نفس منهجية «وصف حالة الاستخدام» بجدول، نفس ثنائية drawio (مصدر قابل للتحرير) + SVG (عرض).
4. **المصدر الأعلى عند التعارض**: وثيقة 40 (سجل السياسات) ← ثم النموذج المجمد v1.0 ← ثم بقية الوثائق.
5. **بوابة مالك لكل محطة**: لا انتقال لمحطة تالية قبل توقيع المالك على مخرج المحطة الحالية، ويُسجل في 31A.
6. **الورشة موازية لمسار فلاتر**: لا تحجب كرسر أبدًا؛ وأي مخرج يخدم فلاتر (ERD/Class/Use-Case) يُشار إليه في handoff.
7. **فحص آلي قبل كل بوابة**: سكربت `docs_academic/tools/verify_docs.py` يتحقق أن كل حقل مذكور في جداول الفصل الرابع موجود فعلًا في schema.sql، وأن كل شاشة/خدمة مذكورة موجودة في _REGISTRY.

## ب) بنية الإنتاج في المستودع
```

   │  ├─ ch1_مقدمة.md  ch2_دراسات_سابقة.md  ch3_تحليل_ونمذجة.md  ch4_تصميم.md

   │  └─ svg/   *.svg                ← التصدير للعرض والتضمين
   ├─ references/                    ← قائمة المراجع (APA) + روابط الدراسات
```

## ج) المحطات الثلاث عشرة

### 🏗 و٠ — تجهيز البنية والقالب
**المخرج**: شجرة docs_academic كاملة + قالب docx (غلاف، أنماط عناوين RTL بخط Cairo، ترويسة/تذييل، تعريف ترقيم «شكل ٣-١»/«جدول ٤-٢») + سكربتا tools + صفحة عينة بكل الأنماط ليوقّع عليها المالك.
**المصدر**: نسق المرجع + 15_DESIGN_SYSTEM (الهوية).
**القبول**: المالك يرى صفحة العينة ويعتمد الشكل قبل كتابة أي محتوى.

### 📘 الفصل الأول — المقدمة (محطتان)
**و١ — نظرة عامة + بيان المشكلة المتفرع**
بنسق المرجع حرفيًا: فقرة نظرة عامة ← المشكلة العامة ← «وتتفرع المشكلة العامة إلى المشكلات الآتية:» مع ٥ مشكلات فرعية معنونة ومشروحة (المرشحة من وثائقنا: ١) تشتت أدوات الرقابة وتحولها لعلاقة مراقبة لا تربية، ٢) غياب عملة تحفيزية موحدة تربط الإنجاز بوقت الشاشة، ٣) انعدام الشفافية — الحلول القائمة تعتمد الخداع والتجسس، ٤) غياب الطرف الموسع (الجد/الأقارب) من المنظومة، ٥) عدم ملاءمة الحلول الأجنبية للسياق العربي/الأسري).
**المصدر**: 00_READINESS_BRIEF، 03، 27. **القبول**: المالك يعتمد صياغة المشكلات الخمس.

**و٢ — الأهداف + النطاق + المنهجية**
الأهداف (عام + فرعية مرقمة مشتقة من الدومينات الخمسة) · النطاق: جدول In-Scope (129 شاشة/5 أدوار/الدومينات) وOut-of-Scope (الباك-إند الحي، iOS أولًا، المدفوعات المالية… من حدود v1.0 وADR-032) · **جدول المنهجية بنسق المرجع** («المرحلة/الأعمال/المخرج المتوقع» ×٨ صفوف) — منهجيتنا الفعلية الموثقة: نماذج أولية + موجات + محطات صقل + تدقيق ٥٤ نظامًا + تجميد v1.0 + تحويل فلاتر.
**المصدر**: 13، 28، 42، 43. **القبول**: توقيع المالك.

### 📗 الفصل الثاني — الدراسات السابقة (محطتان)
**و٣ — المنصات المشابهة (بحث ويب حقيقي)**
٥–٦ منصات بجدول المرجع («المنتج/الدولة أو الجهة/الوظائف الرئيسة/علاقته بمشروعنا»): Google Family Link، Qustodio، Bark، Aura/Kaspersky Safe Kids، ومنصة عربية (تُبحث). لكل منصة فقرة وصفية + نقد.
**المصدر**: 03_COMPETITIVE_PARITY + بحث ويب محدث ٢٠٢٥/٢٠٢٦. **القبول**: المالك يعتمد قائمة المنصات قبل التوسع.

**و٤ — الدراسات العلمية + جدول المقارنة + الفجوة + المراجع**
دراستان علميتان محكمتان (٢٠٢٣–٢٠٢٥) عن الرقابة الأبوية الرقمية/الرفاه الرقمي للأطفال (بحث حقيقي بمراجع APA) ← جدول مقارنة شامل (المنصات × المزايا: عملة الدقائق، الشفافية، الأدوار الموسعة، الذكاء الاصطناعي التربوي، العربية) ← فقرة «الفجوة البحثية» التي يسدها «عائلتي» ← قائمة مراجع.
**القبول**: توقيع المالك على الفجوة (هي هوية المشروع).

### 📙 الفصل الثالث — التحليل والنمذجة (٥ محطات)
**و٥ — أدوات جمع البيانات + المتطلبات**
أدوات الجمع (منهجيتنا الفعلية: تحليل منافسين، جلسات المالك الموثقة ع-١/ق-٨/محاضر ٣٢–٣٧، النماذج الأولية التفاعلية كأداة تحقق) · **المتطلبات الوظيفية** FR-001… مرقمة بجداول مجمعة حسب الدومينات الخمسة (تجميع الـ240 خدمة في ~40–50 متطلبًا رئيسيًا مع Traceability لأرقام الخدمات) · **غير الوظيفية** NFR (offline-first، الأداء، الأمان، العربية RTL، القابلية للتوسع — من 42/43).
**المصدر**: _REGISTRY/services.csv، 05–12، 40. **القبول**: المالك يعتمد مستوى التجميع.

**و٦ — سيناريوهات الأدوار الخمسة**
بنسق سيناريوهات المرجع: عبدالله (الأب المالك — يوم كامل: إسناد مهمة، اعتماد، طوارئ)، نوال (الأم المفوضة وحدود التفويض)، خالد ١٤ (مهمة→دقائق→محفظة تطبيق→طلب وقت إضافي)، نورة ١١/سعد ٨ (الفروق العمرية + المعلم الذكي)، الجد سالم (الدور الموسع). كل سيناريو سردي + خطوات مرقمة.
**المصدر**: 41_FINAL_WALKTHROUGH + handoff/05. **القبول**: توقيع المالك.

**و٧ — Use Case Diagram + جداول وصف الحالات**
مخطط حالات استخدام drawio+SVG: ٥ فاعلين × مجموعات الخدمات (بنسق مخطط المرجع: نظام مركزي + Extends/Includes) + **١٠ جداول وصف حالة استخدام** بنسق جداول المرجع (اسم الحالة/الفاعل/الشرط المسبق/المسار الأساسي/المسارات البديلة/الشرط اللاحق) للحالات الجوهرية: إنشاء العائلة وربط جهاز، إسناد مهمة بمكافأة دقائق، اعتماد إنجاز، إدارة محافظ التطبيقات، طلب وقت إضافي، SOS، الوضع الذكي، تفويض الأم، اقتراح المستشار→اعتماد، التقارير.
**القبول**: المالك يفتح المخطط ويوقع.

**و٨ — مخططات التسلسل الأربعة (Sequence)**
بنفس أسلوب SVG المرجع: ١) إسناد مهمة → إنجاز → اعتماد → إيداع دقائق في المحفظة، ٢) طلب وقت إضافي → قرار الأب → فتح/بقاء القفل، ٣) SOS → إشعار متعدد الأطراف → التصعيد، ٤) حدث عائلي → المستشار (Gateway بلا تنفيذ ذاتي — ADR-033) → اقتراح → اعتماد الأب → تطبيق.
**المصدر**: 40 (أحكام أ/ب/جـ/د + ق٢) + 08_AI_CORE_CHARTER. **القبول**: توقيع.

**و٩ — مخططات النشاط الأربعة (Activity)**
١) دورة حياة المهمة والمكافأة (بممرات Swimlanes أب/ابن/نظام)، ٢) محرك الوقت وسلم الأولوية (قفل انتهاء الرصيد، حظر الأب الصلب، محافظ التطبيقات ق-٢)، ٣) دورة الوضع الذكي (تفعيل/استثناءات/انتهاء)، ٤) ربط جهاز ابن جديد (pairing_token من schema).
**القبول**: توقيع → **بوابة كبرى: اكتمال الفصل الثالث**.

### 📕 الفصل الرابع — التصميم (٣ محطات)
**و١٠ — أدوات التطوير + ERD + تحليل الكيانات**
أدوات التطوير المقترحة بجدول (Flutter/Dart، Riverpod، Drift، drawio… من 43 وhandoff/02) · **ERD** drawio+SVG للكيانات العشرين وعلاقاتها (مشتق حرفيًا من schema.sql: account→family→member→child→device→device_permission… geofence، sos_alert، conversation/message، ai_suggestion، audit_log) · فقرة تحليل لكل مجموعة كيانات.
**القبول**: المالك يطابق ERD مع فهمه للنظام.

**و١١ — المخطط العلائقي + جداول «الحقل/الوصف» العشرون**
بنسق المرجع تمامًا (هو أنتج ١٣ جدولًا؛ نحن ٢٠): جدول لكل جدول قاعدة بيانات — كل صف: الحقل/النوع/الوصف بالعربية + المفاتيح. **يمر إجباريًا على verify_docs.py** (تطابق ١٠٠٪ مع schema.sql).
**القبول**: تقرير الفحص الآلي أخضر + توقيع.

**و١٢ — Class Diagram**
مخطط أصناف للكيانات الدستورية والطبقات (من ADR-032): Repositories الواجهات، TimeEngine، PolicyEngine، MinutesWallet، AppWallet، FamilyMode، AiSuggestion (بلا execute)، EventBus — يخدم كرسر مباشرة في مرحلة الدومين.
**القبول**: توقيع → اكتمال الفصل الرابع.

### 📦 و١٣ — التجميع والتسليم
build_docx.py يجمع الفصول الأربعة في **التوثيق_عائلتي.docx** واحدة: غلاف + فهرس آلي + قائمة أشكال + قائمة جداول + الفصول + المراجع + ملاحق (لوحة الـ٥٤، سجل ADR ملخصًا) · مراجعة إملائية/اتساق مصطلحات (قاموس موحد: الدقائق، المحفظة، المستشار…) · **ملخص إنجليزي تنفيذي** يُضاف كـ `handoff/11_ACADEMIC_DOC_SUMMARY.md` لكرسر · كوميت + دفع.
**القبول**: بوابة نهائية — المالك يقرأ الوثيقة الكاملة ويوقع.
