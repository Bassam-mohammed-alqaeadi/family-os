| **MODE-OD-07** | Q-MODE-07 | **Modes are tighten-only.** May restrict relative to underlying policy; must **not** reopen Permanent App Blocks; weaken FS-004 permanently; rewrite FS-002 URL lists; bypass higher-priority safety; or create a lower-priority path that defeats existing restrictions. | **MODE-OD-08** | Q-MODE-08 | **FS-005 owns lifestyle scheduling authority.** Supported schedule semantics are represented by FS-005 and evaluated through **one canonical** scheduling/evaluation path. | **MODE-OD-09** | Q-MODE-09 | Enable all four activation channels: (1) **Manual** (2) **Clock/schedule** (3) **Location/geofence-derived context from FS-001** (4) **Seasonal/date-range**. | **MODE-OD-10** | Q-MODE-10 | Child **must see** active Mode and relevant restriction/grace state. Grace is a **parent-/Mode-defined transition**, not child authorization to cancel policy. | **MODE-OD-12** | Q-MODE-12 | Modes may overlay: FS-003 · FS-002 · FS-004 · location-derived contextual behavior · Screen Time **context** (Kernel interaction only). Modes do **not** own: package policy storage · URL lists · geofence definitions · camera enforcement mechanisms · ST wallets/minutes/grants. |
| **MODE-OD-13** | Q-MODE-13 | **Primary + Full configure Modes.** Partner may: view Mode state; receive relevant Mode notifications; perform **explicitly authorized** activation/deactivation only where the global ticket/operational model permits. Partner is **not** a Mode policy editor. Observer = view-only. |
| **MODE-OD-14** | Q-MODE-14 | **SOS** reachable regardless of Mode. **Required Family Chat** reachable. **Quran** required-access path reachable. Modes never override SOS safety. No Mode may create an emergency lockout. |
