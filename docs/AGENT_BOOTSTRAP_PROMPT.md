## أمر تشغيلي إلزامي — Family OS

أنت تعمل على مستودع `Bassam-mohammed-alqaeadi/family-os`. قبل أي شيء، اعتمد هذه الاستراتيجية وطبّقها بلا استثناء.

### القانون الحاكم

**مساحة العمل مؤقتة، وGitHub هو المصدر الوحيد للحقيقة.**

مساحة العمل قد تُمسح في أي لحظة. أي شيء لا يوجد على GitHub اعتبره غير موجود. ومعيار نجاحك: **لو مُسحت مساحة العمل الآن، لا يضيع شيء.** والاستعادة تساوي `git clone` ثم `install` فقط.

### سبع قواعد غير قابلة للتفاوض

1. **لا مُشتقّات في Git أبداً.** ممنوع تتبع: `node_modules/`، `build/`، `dist/`، `out/`، `.dart_tool/`، `.venv/`، `coverage/`، `.next/`، `target/`، `__pycache__/`، وأي `*.zip` / `*.tar.gz` / `*.apk` / `*.so` / `*.dll` / `*.pyc`. وتأكد أن `.gitignore` يغطيها. تاريخ Git لا يُمحى: ملف كبير يُودَع مرة يبقى في كل استنساخ إلى الأبد، والمستودع يصبح ثقيلاً ثم غير قابل للعمل.
2. **لا تدفع مفتاحاً ولا سراً.** لا `service-account*.json`، لا `firebase-adminsdk*`، لا `.env`، لا `*.pem`. والفحص على **المحتوى** لا على الاسم.
3. **ادفع في نهاية كل وحدة عمل.** لا تُنهِ دورك وأنت تحمل عملاً ذا قيمة غير مدفوع. إيداع واحد = تغيير واحد قابل للفهم.
4. **لا `force-push` أبداً، ولا حذف أو إعادة تسمية للفرع أو المستودع.**
5. **لا تدّعِ ما لم تشغّله.** إن قلتَ «الاختبارات ناجحة» فاذكر الأمر والرقم الحقيقي. النية ليست دليلاً.
6. **سجّل الفشل كما هو.** إن تعذّر شيء أو رُفض طلب أو فشل اختبار، اكتبه صريحاً. السجل الصادق يُبنى عليه، والمُجمَّل ينهار عند أول ضغط.
7. **اعمل على فرعك فقط، ولا تلمس فرعاً آخر.** لكل جلسة مساحة عمل مستقلة.

### دورة العمل — أوامر جاهزة

**في بداية كل جلسة — زامن أولاً، لا تفترض:**
```bash
git fetch origin
git status -sb          # أنا على الفرع الصحيح؟ هل معي إيداعات غير مدفوعة؟
git log --oneline -5    # أين وصل العمل؟
```
إن وجدتَ إيداعات محلية غير مدفوعة، **ادفعها قبل أي عمل جديد**.

**أثناء العمل — بعد كل وحدة مكتملة:**
```bash
git add -A
git commit -m "<نوع>(<نطاق>): الفعل

لماذا: السبب الحقيقي.
التحقّق: الأمر → النتيجة بالأرقام (مثال: 93/93 ناجح، 0 فاشل)."
```

**في نهاية كل جلسة — ثلاثة أوامر لا تُنسى:**
```bash
git add -A && git commit -m "..."    # ١) كل تغيير محفوظ
git push origin <فرعك>               # ٢) كل شيء على GitHub
bash /tmp/repo-health.sh             # ٣) دليل أن مساحة العمل آمنة (انظر أدناه)
```

**فحص السلامة** — نزّله في `/tmp` **ولا تُودِعه** (تجنّباً لأي تصادم مع فرع آخر):
```bash
curl -fsSL https://raw.githubusercontent.com/Bassam-mohammed-alqaeadi/family-os/arena/6233f1a1-family-os/tools/git/repo-health.sh -o /tmp/repo-health.sh
bash /tmp/repo-health.sh
```
إن تعذّر التنزيل، نفّذ الفحص يدوياً:
```bash
git status --porcelain          # هل يوجد ما هو غير مُودَع؟
git log origin/<فرعك>..HEAD    # هل يوجد إيداع غير مدفوع؟ (يجب أن يكون فارغاً)
git ls-files | grep -E '(node_modules|/build/|\.dart_tool|dist/|\.zip$)'   # يجب أن يكون فارغاً
du -sh .git                     # الميزانية: تحت ١٠٠ ميجابايت
```

**حكمك النهائي:** `exit 0` من الفحص = آمن للتخلّي عن مساحة العمل. أما `exit 1` فلا تُنهِ الجلسة قبله.

### الاستعادة الكاملة إن ضاعت مساحة العمل

```bash
git clone https://github.com/Bassam-mohammed-alqaeadi/family-os.git
cd family-os && git switch <فرعك>
npm ci --prefix backend     # مكتبات Node
flutter pub get             # مكتبات Dart
```
هذا كل شيء. **إن احتجت خطوة إضافية، فالمستودع ليس نظيفاً** — أصلح السبب لا النتيجة.

### إن وجدتَ إيداعات محلية قديمة أو مساحة عمل أُعيد بناؤها
```bash
git fetch origin
git reset --hard origin/<فرعك>    # بعد التأكد أن كل محتوى مهم موجود في تاريخ الريموت
```
**وقبل أي حذف:** تحقّق أن محتوى كل ملف غير مُودَع موجود في تاريخ المستودع. **ولا force-push في أي حال.**

### قراءة CI بصدق — أهم مهارة هنا

- **فخ `continue-on-error`:** خطوة تحمله تُسجَّل `success` **وهي فاشلة**. علامة النجاح الحقيقية أن خطوة «الإنفاذ» (Enforce) تكون **`skipped`** — فهي تُشغَّل فقط عند وجود فشل.
- **اقرأ من مصدر الحقيقة لا من الملخّص:**
  ```bash
  gh api repos/<owner>/<repo>/actions/runs/<run_id>/jobs --jq '.jobs[].steps[] | "\(.conclusion)\t\(.name)"'
  gh api repos/<owner>/<repo>/check-runs/<job_id>/annotations --jq '.[] | select(.annotation_level=="failure") | .message'
  ```
- **«لم يُحجز رُندر»** (`runner_name: ""` + «The job was not acquired by Runner of type hosted») = **بنية تحتية، لا فشل كود**. سجّلها كذلك، وأعد المحاولة بدفعة جديدة، ولا تخلطها بفشل حقيقي.
- **لا تفترض أن انعطاف CI سببه عملك.** شغّل CI على **الالتزام الأساسي** قبل أن تبدأ وسجّل الأرقام، ثم قارن بعده. إن بقي عدد الفاشل كما هو وزاد الناجح، فأنت لم تُدخل فشلاً (جدول «الكناري»).
- **ممنوع تعلّق نجاحك على CI إن لم يحصل على رُندر.** ما لا تستطيع تشغيله، لا تدّعِ نجاحه — انقله إلى CI وانتظر حكمه.

### قواعد فنية تحمي من أخطاء صامته

- **نهايات الأسطر:** بعض ملفات Dart تستخدم `CRLF`. عدّلها بأدوات تحفظ البايتات، وتحقّق بعدّاد قبل وبعد — الخطأ هنا لا يظهر في المراجعة العادية.
- **الأذونات:** السكربت الجديد يحتاج `chmod +x` وإلا فشل صامتاً.
- **البِنايات المطابقة:** استخدم `npm ci` و `flutter pub get --enforce-lockfile`.
- **الملفات المولَّدة المتتبَّعة:** شغّل خطوة التوليد في CI وتحقّق أن لا فرق، وإلا انحرف المولَّد عن المصدر بصمت.
- **⚠️ تصادم أرقام الـmigration:** الفرع `arena/6233f1a1-family-os` أضاف `009_ai_events.sql`، والفرع `arena/01a10887-family-os` أضاف `009_pairing_code_short_numeric.sql`. الأسماء مختلفة فـGit سيدمجهما **بصمت** بينما `schema-manifest.js` يحمل `009` مرتين بترتيب غير معرّف — عطل قاعدة بيانات لا يظهر في المراجعة. **أي فرع يُدمج ثانياً يجب أن يُعيد الترقيم قبله، ويفحص المراجع في `schema-manifest.js`.**

## للمالك: كيف تستخدم هذا الملف

| الحالة | ما تفعله |
|---|---|
| **وكيل جديد في محادثة جديدة** | انسخ المقطع وضعه في أول رسالة قبل طلبك. |
| **جلسة قائمة تحمّل ملفات في مساحة العمل** | الصق نفس المقطع — سيفحص حالته ويصحّح مساره. |
| **تريد التأكد فقط بلا وكيل** | اطلب منه تشغيل `bash /tmp/repo-health.sh` وأظهر لك `exit 0`. |

**الاختبار الذي لا يكذب:** اطلب من أي جلسة أن تنفّذ الفحص وتُريك النتيجة.
`exit 0` = عملك محفوظ. `exit 1` = لا تسمح لها بالإغلاق قبل أن تُصلحه.

**وتذكّر:** لا يمكن أن يضيع عملك بسبب إيقاف الموقع. العمل المدفوع على GitHub يبقى في GitHub مهما حدث لأي مساحة عمل. الشيء الوحيد الذي يضيع هو **ما لم يُدفع** — ولهذا القاعدة الثالثة أعلاه.
