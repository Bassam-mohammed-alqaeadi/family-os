# Family Intelligence — Phase Initiation

> **Loop card:** INTELLIGENCE-G1-DISCOVERY
> **Status:** Active; G1 direction accepted under standing Owner trust
> **Goal:** Make intelligence a transparent family decision-support plane built from real, source-qualified platform events—not a chatbot veneer, hidden surveillance layer, or autonomous parent substitute.

## 1. Product outcome

Family Intelligence helps a guardian understand meaningful changes across security, learning, connection and family operations, then choose a proportionate next action.

| Person | Essential question |
|---|---|
| Primary guardian | “What changed, how certain is it, why does it matter, and what is a sensible next step?” |
| Co-guardian | “What analysis is relevant to my role and what may I act on?” |
| Child | “When an insight affects me, is it explained respectfully and can I understand or respond to it?” |
| Family platform | “Can source facts, uncertainty, consent, privacy, and human control remain intact from event to recommendation?” |

## 2. The Intelligence Loop

```text
Source-qualified event from Security / Learning / Connection / Administration
  → validation, permission and data-quality check
  → signal or baseline update
  → pattern/anomaly only when evidence is sufficient
  → explainable insight / report / recommendation
  → guardian reviews, acts, defers, rejects or corrects it
  → resulting action and outcome are audited
  → model/rule confidence improves or recommendation retires
```

An intelligence screen cannot treat a model output, risk score, raw signal, or missing data as a verified family fact.

## 3. Registered intelligence universe

The active pillar contains 6 systems and 34 services:

1. Signal engine.
2. Patterns and anomaly engine.
3. Family knowledge store.
4. Advisor and reports.
5. Interactive assistant.
6. Delegated agent.

## 4. Direction principles

1. **Facts before inference.** Every signal, pattern, recommendation and action can identify its source event/data quality.
2. **Uncertainty is a feature.** “Not enough information” and “I do not know” are valid outcomes.
3. **Explain before act.** A guardian can see why an insight appeared and what the system did not know.
4. **Suggest, do not punish.** Intelligence cannot autonomously impose a safety/learning/social consequence.
5. **Delegation is narrow and reversible.** Any agent action needs explicit scope, limit, audit, notification and real undo/reversal model.
6. **Least data, purposeful use.** The knowledge store holds only data required for an approved family value, with visibility/forget/review controls.
7. **Child dignity remains intact.** A child is not reduced to a risk score, profile or hidden behavioral record.
8. **Render controls AI.** Any future provider/model call occurs through Render’s authorized backend boundary, never from a Flutter client or Firebase as a system of record.

## 5. Required platform connections

| Intelligence activity | Required platform tie |
|---|---|
| Signal | Source event, family/child/device scope, source quality, visibility/retention classification. |
| Pattern | Baseline/window, sufficient evidence, confidence, explanation, false-positive/not-useful feedback. |
| Knowledge item | User/guardian visibility, consent, source link, correction, forget/delete lifecycle. |
| Report/advice | Today, notification policy, parent action path, supporting facts, feedback/audit. |
| Assistant answer | Role-aware retrieval, cited family source, “I do not know,” no privilege escalation. |
| Delegated action | Explicit delegation policy, permitted action contract, Render execution, notification/audit, reversal. |

## 6. Scope boundary

### In scope

The six registered intelligence systems are active for product refinement. They are classified below without assuming immediate model/provider deployment.

### Out of scope today

- A generic unsupervised chatbot with access to all family data.
- Fully autonomous child discipline, contact blocking, location escalation, reward changes, spending, or high-impact parent decisions.
- New ambient/audio monitoring candidates.
- Client-side API keys, direct third-party model calls, Firebase-hosted AI as the product source of truth.
- Peer comparison as a default family metric.

## 7. Core journeys to close

1. Parent sees an explainable signal and chooses dialogue/support rather than reflexive punishment.
2. Parent sees a weekly summary with one source-qualified recommendation.
3. Parent asks a natural-language question and receives sourced answer or “I do not know.”
4. Child receives an age-appropriate explanation if an insight leads to a visible plan/routine change.
5. Parent corrects/rejects an unhelpful recommendation, and the platform records feedback.
6. Parent creates a narrow delegated rule and can see, undo and audit every action.
