# Learning Implementation Sequence — Gate G3

> **Status:** Build-ready roadmap; no Backend, Native, AI, or content-ingestion implementation authorized yet.
> **Goal:** Make learning real through closed child/guardian loops, not by separately implementing many attractive screens.

## 1. Delivery strategy

Learning is delivered as vertical slices on the shared Family OS spine. Each slice must join guardian intent, child experience, data/evidence, notification/timeline, security/focus coordination, and recovery.

```text
Shared family + device + policy + event foundation
  → closed child/guardian learning slice
  → validate content/result truth
  → extend to the next learning capability
  → introduce AI/adaptation only when evidence and governance are ready
```

## 2. Learning foundation

| Foundation capability | Why it comes first |
|---|---|
| Family roles, child profiles, device/capability context | Determines who can create, approve, see, learn, and support. |
| Content/artifact provenance and revision | Makes Studio/material lifecycle trustworthy. |
| Assignment/plan lifecycle | Turns a guardian’s action into a clear child next step and result. |
| Activity/event/timeline foundation | Supports Today, notifications, reports, guardian coordination, and audit. |
| Focus/security contract | Ensures study routines use truthful time/device behavior. |
| Privacy and support boundaries | Protects child work, tutor context, Quran progress, and content sources. |

## 3. Proposed vertical sequence

### Slice 1 — Child plan, lesson, and assignment loop

Guardian selects/approves an existing artifact, assigns it with a due context; child sees, starts, completes/submits; guardian receives a clear state and follow-up.

Includes: child home, parent Learning Hub, artifact revision, assignment lifecycle, local/offline/delivery truth, calendar/task/notification/timeline link, child explanation, co-guardian visibility.

### Slice 2 — Formative assessment and constructive result loop

Child takes a valid practice/assessment, receives appropriate feedback/retry, and guardian sees a contextual result rather than a raw score.

Includes: attempt lifecycle, feedback/result source, accessibility/accommodation, result/report baseline, learning evidence, recovery for interrupted work.

### Slice 3 — Focus and study-routine loop

Child starts a learning-related focus session; security/time/school policy reports actual state; guardian sees a truthful routine/result.

Includes: plan/calendar link, security command/receipt integration, essential access, time-zone conflict, focus activity event, parent support state.

### Slice 4 — Recognition and permitted privilege loop

Genuine learning effort/progress creates non-financial recognition; an optional time privilege is created only through explicit security policy and expiry.

Includes: evidence-linked reward, child celebration, guardian policy, audit/correction, cross-pillar time exception receipt.

### Slice 5 — Parent Studio reviewed-content loop

Guardian creates/manual-composes or selects an approved source, reviews/approves a revision, assigns it, and sees child outcome.

Includes: source/provenance, draft/review/approval/withdraw/archive, assignment integration, content quality/support, reuse.

### Slice 6 — Quran elective learning-path loop

Family selects an optional Quran plan; child follows manageable ward/review/recitation/adhkar routine; guardian sees respectful progress and support option.

Includes: path selection, plan/activity/progress, focus/routine connection, child/guardian views, capability truth for audio/recitation.

### Slice 7 — Adaptive plan and guided tutor

Evidence supports a transparent recommendation; child gets guided help; guardian sees appropriate support insight; feedback improves/retires the recommendation.

Includes: skill evidence, confidence, insufficiency state, grounded tutor, guardrails, review/feedback, no-answer policy.

### Slice 8 — Advanced input, generation, community, and creative systems

Camera/OCR, file/link/voice intake, generation, auto-grading, recitation correction, community publishing, interactive stories, and competitions begin only after their content/AI/capability/governance decisions are independently complete.

## 4. Definition of done per slice

A learning slice is complete only if:

1. Guardian/co-guardian/child journeys close end-to-end.
2. Approved UX and all relevant states are implemented without rearranging the product architecture.
3. Content source/revision/approval and assignment/result lineage are traceable.
4. Delivery, offline, duplicate, conflict, expiry, withdrawal, and recovery behavior are tested.
5. Child-facing language supports autonomy and dignity.
6. Focus/security/reward connections use explicit shared contracts when relevant.
7. Capability limits are visible and no unavailable source/AI/media/assessment behavior is implied.
8. Accessibility, RTL/LTR, localization, time-zone, age, and data-boundary checks pass.
9. Support, audit, monitoring, and rollback conditions are ready.
10. Real-device/pilot validation exists for every public technical/content/AI claim.

## 5. Authorization boundary

This is a readiness roadmap, not authority to begin Backend, Native, AI-provider, content-provider, camera, speech, or release implementation. The Owner must authorize that execution phase explicitly after broader product-refinement sequencing is complete.
