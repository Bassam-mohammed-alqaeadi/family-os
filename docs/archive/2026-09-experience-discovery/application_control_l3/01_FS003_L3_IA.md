## 1. UX principle

App Control is a **package-access gate** with **honest enforcement claims**.

Parents author **access policy** (Allow / Permanent Block / Exempt), govern **new installs**, decide **App Access Exceptions**, and apply **Lock Now** overlays.  
Children meet App Control only through **deny/pending surfaces + Exception Request** — never admin.  
**Configured policy ≠ enforced on device** until verified plane + acknowledgement prove it.

IA is organized by **role job**, not Stage-1 screen filenames (FAT-034/035 are non-authority).

---

## 2. Role-level mental models

| Role | Job-to-be-done | Product shape |
|---|---|---|
| **Primary Parent** | Author family + child access policy; Permanent Block set/reopen; Lock Now; Restore Baseline; install/exception decide; honesty; audit | Full App Control suite |
| **Co-Parent Full** | Configure + set Permanent Block + Lock Now + Restore; install/exception decide; **cannot** reopen Permanent Block | Configure + tickets − reopen |
| **Co-Parent Partner** | Decide install + Exception tickets; view summary + honesty; **no** configure / Lock Now / Restore / Permanent Block | Tickets + read-only |
| **Co-Parent Observer** | View summary + honesty + inventory status; **no** mutation / decide | Read-only |
| **Child** | Deny/pending interstitial; Exception Request; protection-active disclosure | **No** admin |

## 3. Parent Information Architecture

### 3.1 Logical nav (not final chrome)

```
Parent shell
 └─ التحكم بالتطبيقات / App Control  (family system hub)
     ├─ OVERVIEW …………………… honesty + pending tickets + shortcuts
     ├─ FAMILY BASELINE …………… family default access rules (APP-OD-01)
     │    ├─ Class defaults (optional)
     │    └─ Protected surfaces legend (SOS / Family OS / Chat / Quran)
     ├─ PER-CHILD
     │    ├─ Child selector
     │    ├─ Effective summary (baseline vs override)
     │    ├─ Child override editor (create / edit / clear via Restore)
     │    ├─ Installed inventory (package ID + label)
     │    ├─ App detail (access actions)
     │    └─ Device / enforcement status (per enrolled device)
     ├─ INSTALL INBOX …………… pending new/unknown packages
     ├─ EXCEPTION INBOX ……… App Access Exception tickets
     ├─ DECISIONS / AUDIT …… policy + install + exception + relevant denies + plane
     └─ (no scheduler here — deep link Modes)

Cross-links (not owned by App Control IA):
 ├─ FS-005 Modes ……………… schedule / tighten context (consume only)
 ├─ Screen Time ……………… Limit / Unlimited / Countable / Temporary Grant (deep link)
 ├─ FS-002 Web Filtering …… source-of-deny / browser package vs URL
 ├─ Instant Device Lock …… distinct from Lock Now / Permanent Block
 ├─ Anti-tamper ……………… separate subsystem (honesty may deep-link)
 ├─ SOS ………………………… ungated; never denied by App Control
 └─ Notifications …………… install / exception / plane degraded
```

### 3.2 Capability → IA home

| Capability | Lives in | Notes |
|---|---|---|
| Family baseline | FAMILY BASELINE | Required |
| Per-child override | PER-CHILD override | Optional; wins when present |
| Inventory | PER-CHILD inventory | Package ID key; no slug-as-key |
| Allow / Permanent Block / Exempt | App detail | Configure roles only; reopen block = Primary |
| Lock Now | App detail | Temporary deny overlay |
| Protected apps | Legend + locked rows | Cannot deny SOS/Family OS/Chat/Quran |
| Unknown / pending | Inventory badge + INSTALL INBOX | Deny-until-approved |
| Install decide | INSTALL INBOX | Primary+Partner+Full; child-scoped |
| Exception decide | EXCEPTION INBOX | Primary+Partner+Full; timed; no rewrite block |
| Restore Baseline | PER-CHILD | Clears overrides + overlays; not Permanent Block reopen |
| Modes schedule | **FS-005** only | Chip “Mode tightening” when active |
| ST limits / Unlimited | **Screen Time** deep link | Not editable in App Control |
| Enforcement honesty | OVERVIEW + device status | Never false “fully protected” |
| Audit | DECISIONS / AUDIT | No full open-app surveillance |
| Source-of-deny | Deny detail + child interstitial | App / Web / both / Mode / ST |

### 3.3 Parent surface stack

| Layer | Content |
|---|---|
| **App bar** | Title · family/child context · SOS ungated |
| **Honesty strip** | Plane state · ack pending · Mode tighten chip · multi-device summary |
| **Scope switch** | Family baseline \| This child’s effective / override |
| **Body** | Inventory / detail / inbox / audit |
| **Sheets** | Confirm Permanent Block · Lock Now duration TBD · Exception decide · Restore confirm · Offline queued |
| **Forbidden in body** | Duration invent · DO/Accessibility as claimed mechanism · ST Limit editors · Mode schedule editor |

## 4. Child Information Architecture

```
Child experience (App Control facing)
 ├─ DENY / PENDING INTERSTITIAL …… source-of-deny + disclosure
 ├─ EXCEPTION REQUEST ……………… when blocked/pending allows request
 ├─ PROTECTION-ACTIVE DISCLOSURE … non-interactive
 └─ SOS / Required Chat / Quran …… always reachable (outside deny)
```

**Forbidden child branches:** policy editor · inventory admin · install decide · reopen block · Lock Now · Restore · audit export · ST Unlimited authoring · Web Filter admin · Anti-tamper admin · enforcement diagnostics beyond disclosure.
