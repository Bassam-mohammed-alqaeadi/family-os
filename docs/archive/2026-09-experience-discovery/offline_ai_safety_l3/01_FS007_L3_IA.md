## 1. UX principle

Parents **configure** on-device safety classification, **receive honest notifications**, and **review gated tickets** with metadata + redacted previews.  
Children see a **permanent transparency card** naming active tools and on-device/offline analysis — never admin.  
**Configured ≠ classifying** until signed model present, version acked, and capability plane verified.  
**No fixture detections. No fake cloud classify. No fake “protected.”**

---

## 2. Role mental models

| Role | Job |
|---|---|
| **Primary / Full** | Configure tools; apply/rollback models; review tickets; see metadata+preview; receive notifies |
| **Partner** | Receive notifies; review tickets; **no** configure / model apply |
| **Observer** | View-only summary/honesty if exposed; **no** FS-007 push; **no** ticket action |
| **Child** | Transparency card only |

## 3. Parent IA (logical)

```
Parent shell
 └─ Offline AI Safety / Smart monitoring (FS-007 hub)
     ├─ OVERVIEW ……… honesty · model version · last classify · pending tickets
     ├─ TOOLS ………… Search · Image · (Screenshot status link → FS-004 policy)
     ├─ MODEL / ASSETS … version · signed state · apply/rollback (Primary+Full)
     ├─ INBOX / TICKETS … gated review queue
     ├─ TICKET DETAIL … metadata · redacted preview · actions (FP / resolve / suggest)
     ├─ NOTIFICATIONS … safety notify history
     ├─ DEVICES / ACK … per child device model+policy ack · degraded matrix
     └─ AUDIT ………… classify · notify · ticket · model apply (append-only)

Cross-links (not owned):
 ├─ FS-004 Screenshot monitoring policy editor
 ├─ FS-002 / FS-003 suggestion deep-links (human approve only)
 ├─ FS-005 Mode suggestions (human approve only)
 └─ Advisor FAB …… adjacent; not FS-007 classify admin
```
