---

## 1. UX principle

Web Filtering is a **family protection gate** with **honest enforcement claims**.

Parents author **policy** and review **decisions / unlocks / device status**.  
Children meet the filter only through **block interstitial + non-interactive “family filter active” disclosure** (WF-OD-15).  
**Configured policy ≠ enforced traffic** until verified plane + device acknowledgement prove it (WF-OD-04 · WF-SF-10 · L3.6).

IA is organized by **role job**, not Stage-1 screen filenames.

---

## 2. Role-level mental models

| Role | Job-to-be-done | Product shape |
|---|---|---|
| **Primary Parent** | Author family + child policies; lists; Safe Search; unlocks; enforcement honesty; audit/decision history; optional router add-on (honest) | Full Web Filter suite |
| **Co-Parent Full** | Same configure + unlock as Primary for filter **except** Primary-leaning owner-only export class (WF-SF-06) | Configure + unlock + view |
| **Co-Parent Partner** | Approve/deny unlocks; view policy summary + status; **no** core policy/list edit (WF-OD-02/03) | Unlock + read-only policy |
| **Co-Parent Observer** | View summary + enforcement honesty; **no** edit; **no** unlock decide | Read-only |
| **Child** | See block; optional unlock request; filter-active disclosure | **No** admin / lists / categories / integrity |

## 3. Primary / Co-Parent Information Architecture

### 3.1 Logical nav (not final chrome)

```
Parent shell
 └─ حماية الويب / Web Filtering  (family system hub)
     ├─ OVERVIEW ……………………… effective protection honesty + shortcuts
     ├─ FAMILY BASELINE …………… family default policy (WF-OD-01)
     │    ├─ Categories
     │    ├─ Allowlist
     │    ├─ Blocklist
     │    ├─ Keyword dictionary
     │    ├─ Safe Search
     │    └─ Private/incognito capability (honesty only)
     ├─ PER-CHILD
     │    ├─ Child selector
     │    ├─ Effective policy summary (baseline vs override)
     │    ├─ Child override editor (create / edit / remove)
     │    └─ Device / enforcement status (per child device)
     ├─ UNLOCK INBOX ……………… pending + decided temporary exceptions
     ├─ DECISIONS / AUDIT ……… deny + unlock lifecycle (WF-OD-14)
     └─ OPTIONAL ADD-ONS
          └─ Home router DNS (honest optional — not core claim) (WF-OD-11)

Cross-links (not owned by Web Filter IA):
 ├─ FS-005 Modes ……………… schedule / tighten context (consume only)
 ├─ FS-003 App/System Control … stricter intersection; source-of-deny
 ├─ SOS ………………………… ungated; never blocked by filter
 ├─ Screen Time ……………… independent gate; unlock ≠ minutes grant
 └─ Notifications …………… unlock request / decision / plane degraded
```

### 3.2 Capability → IA home

| Capability | Lives in | Notes |
|---|---|---|
| Family baseline policy | FAMILY BASELINE | Required; create if none |
| Per-child override | PER-CHILD override editor | Optional; when present wins for that child |
| Categories | Baseline or Override → Categories | Large normative; labels TBD (T-WF-02) |
| Allowlist / Blocklist / Dictionary | Lists under baseline or override | First-class (WF-OD-08) |
| Safe Search | Baseline/Override toggle + capability honesty | Mandatory where enforceable (WF-OD-06) |
| Private/incognito | Capability honesty panel | Platform matrix (WF-OD-07); no fake “blocked” |
| Unlock/exception inbox | UNLOCK INBOX | Decide: Primary+Partner+Full |
| Enforcement / device status | OVERVIEW + PER-CHILD device status | Never claim “fully protected” falsely |
| Degraded / unsupported | Honesty banners / status cards | WF-SF-10 |
| Audit / decisions | DECISIONS / AUDIT | Deny + unlock lifecycle only |
| Mode schedule | **FS-005** only | Filter shows “active Mode tightening” chip when applicable |
| Router DNS | OPTIONAL ADD-ONS | Explicit “not core on-device” labeling |
| Source-of-deny | Decision detail + child interstitial | Web Filter / App Control / both / Mode |

## 4. Child Information Architecture

```
Child shell
 └─ (browser / web navigation interrupt)
     └─ BLOCK INTERSTITIAL ……… reason class + optional Request unlock
          └─ transient feedback only: pending → approved / denied / expired
             (NOT a separate child destination / admin screen)
 └─ Transparency / compliance
     └─ Non-interactive “family filter active” disclosure …… WF-OD-15
 └─ SOS / required chat / Quran
     └─ Always reachable — never filter-gated (WF-SF-02)
```

**Frozen child surfaces (Q-WF-15):** block interstitial + non-interactive filter-active disclosure **only**.

**Forbidden child IA branches:** unlock-result destination · policy editor · categories · allow/block/dictionary · Safe Search admin · enforcement diagnostics · integrity details · Mode admin · router setup · audit/history · App Control admin.

**Only extra child action:** submit unlock request from interstitial (when Web Filter is the deny source and request is allowed). Decision feedback stays **inside** the interstitial flow.

---

## 5. Notification IA

| Event | Opens |
|---|---|
| Unlock request | Parent UNLOCK INBOX / ticket detail |
| Unlock approved / denied / expired | Parent ticket/history · **Child:** transient feedback on `WF-C-INTERSTITIAL` only (no separate result screen) |
| Policy saved / pending ack | Parent device status |
| Plane degraded / unsupported | Parent OVERVIEW honesty (not SOS-critical misuse) |
| Temporary exception expired | Parent decision history (optional); child transient interstitial feedback only |
| App Control deny (intersection) | May open App Control or joint source-of-deny detail — not a second Web Filter unlock if App Control owns deny |
