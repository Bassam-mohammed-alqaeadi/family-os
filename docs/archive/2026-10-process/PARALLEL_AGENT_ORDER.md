## أمر تشغيلي إلزامي

أنت تعمل على مستودع `Bassam-mohammed-alqaeadi/family-os`، على الفرع **`arena/01a10887-family-os`**.
هناك وكيل آخر يعمل بالتوازي على الفرع `arena/6233f1a1-family-os`. اقرأ هذا الأمر كاملاً ونفّذه بالترتيب.

---

### ١) عاجل — أمّن عملك قبل أي شيء آخر

مساحة عملك قد تُمسح في أي لحظة دون سابق إنذار. **قبل أي إجراء آخر**، نفّذ بالترتيب:

```bash
git status                                   # ما الذي لم يُحفظ بعد؟
git add -A
git commit -m "<صف ما أنجزته فعلاً>"
git push origin arena/01a10887-family-os
```

ثم **تأكّد** أن لا شيء بقي غير مدفوع:

```bash
git log origin/arena/01a10887-family-os..HEAD --oneline
```

يجب أن يكون الناتج **فارغاً**. إن لم يكن فارغاً، فأعد الدفع قبل أن تكمل.

**⛔ محظور تماماً في هذه المرحلة:** لا تنفّذ `git reset --hard`، ولا `git clean`، ولا تحذف أي ملف أو مجلد، ولا تلمس `.git`. عمل غير مدفوع **لا يمكن استعادته**. التأمين أولاً، والتنظيم بعد ذلك.

---

### ٢) القانون الحاكم الذي ستعمل به من الآن

> **مساحة العمل مؤقتة، وGitHub هو المصدر الوحيد للحقيقة.**

مساحة العمل ليست مكان تخزين — هي فقط نسخة عرض مؤقتة. أي شيء لا يوجد على GitHub اعتبره غير موجود.
**معيار نجاحك:** لو مُسحت مساحة العمل الآن، لا يضيع شيء. والاستعادة = `git clone` ثم `install`.

**ولهذا: مساحة العمل خفيفة بحكم التصميم.** لا تحمّل فيها ملفات أو نسخاً احتياطية أو أرشيفات. كل ما تحتاجه يأتي من `git clone`، والمكتبات من `npm ci` و`flutter pub get`.

### ٣) سبع قواعد غير قابلة للتفاوض

1. **لا مُشتقّات في Git.** ممنوع تتبع `node_modules/`, `build/`, `dist/`, `out/`, `.dart_tool/`, `.venv/`, `coverage/`, `__pycache__/`, وأي `*.zip` / `*.apk` / `*.so` / `*.pyc`. تحقّق أن `.gitignore` يغطيها. **تاريخ Git لا يُمحى** — ملف كبير يُودَع مرة يبقى في كل استنساخ إلى الأبد.
2. **لا مفتاح ولا سرّ في Git.** لا `service-account*.json`، لا `firebase-adminsdk*`، لا `.env`، لا `*.pem`. والفحص على **المحتوى** لا على اسم الملف.
3. **ادفع في نهاية كل وحدة عمل.** لا تُنهِ دورك وأنت تحمل عملاً غير مدفوع. إيداع واحد = تغيير واحد قابل للفهم.
4. **لا `force-push` أبداً، ولا حذف أو إعادة تسمية للفرع.**
5. **لا تدّعِ ما لم تشغّله.** إن قلتَ «الاختبارات ناجحة» فاذكر الأمر والرقم الحقيقي. النية ليست دليلاً.
6. **سجّل الفشل كما هو.** إن تعذّر شيء أو رُفض طلب أو فشل اختبار، اكتبه صريحاً. السجل الصادق يُبنى عليه، والمُجمَّل ينهار عند أول ضغط.
7. **فرعك فقط.** لا تدفع إلى `main`، ولا إلى `arena/6233f1a1-family-os`، ولا تعدّل أي ملف في فرع آخر.

### ٤) دورة العمل — الأوامر

**بداية كل جلسة — زامن أولاً، لا تفترض:**
```bash
git fetch origin
git status -sb          # أنا على الفرع الصحيح؟ هل معي إيداعات غير مدفوعة؟
git log --oneline -5
```
إن وجدتَ إيداعات محلية غير مدفوعة، **ادفعها قبل أي عمل جديد**.

**بعد كل وحدة مكتملة:**
```bash
git add -A
git commit -m "<نوع>(<نطاق>): الفعل

لماذا: السبب الحقيقي.
التحقّق: الأمر → النتيجة بالأرقام (مثال: 43/43 ناجح، 0 فاشل)."
git push origin arena/01a10887-family-os
```

**نهاية كل جلسة — ثلاثة أوامر لا تُنسى:**
```bash
git add -A && git commit -m "..."    # ١) كل تغيير محفوظ
git push origin arena/01a10887-family-os   # ٢) كل شيء على GitHub
bash /tmp/repo-health.sh             # ٣) الدليل (انظر القسم ٥)
```

### ٥) فحص السلامة — الاختبار الذي لا يكذب

نزّل الأداة إلى `/tmp` **ولا تُودِعها في المستودع** (إضافتها من عندك تُنشئ تعارضاً مع فرع آخر يضيف نفس الملف):

```bash
curl -fsSL https://raw.githubusercontent.com/Bassam-mohammed-alqaeadi/family-os/arena/6233f1a1-family-os/tools/git/repo-health.sh -o /tmp/repo-health.sh
bash /tmp/repo-health.sh
```

**إن تعذّر التنزيل** (شبكة محجوبة)، نفّذ الفحص يدوياً:
```bash
git status --porcelain                                          # يجب أن يكون فارغاً
git log origin/arena/01a10887-family-os..HEAD --oneline         # يجب أن يكون فارغاً
git ls-files | grep -E '(node_modules|/build/|\.dart_tool|dist/|\.zip$)'   # يجب أن يكون فارغاً
git ls-files | grep -icE '(service-account|adminsdk)\.json$'    # يجب أن يكون 0
du -sh .git                                                     # الميزانية: تحت ١٠٠ ميجابايت
```

**الحكم:** `exit 0` = مساحة عملك آمنة للتخلّي عنها. **`exit 1` = لا تُنهِ جلستك قبل أن تُصلحه.**

### ٨) قراءة CI بصدق

- **فخ `continue-on-error`:** خطوة تحمله تُسجَّل `success` **وهي فاشلة**. علامة النجاح الحقيقية أن خطوة «الإنفاذ» (Enforce) تكون **`skipped`** — فهي تُشغَّل فقط عند وجود فشل.
- **اقرأ من مصدر الحقيقة:**
  ```bash
  gh api repos/Bassam-mohammed-alqaeadi/family-os/actions/runs/<run_id>/jobs --jq '.jobs[].steps[] | "\(.conclusion)\t\(.name)"'
  gh api repos/Bassam-mohammed-alqaeadi/family-os/check-runs/<job_id>/annotations --jq '.[] | select(.annotation_level=="failure") | .message'
  ```
- **«لم يُحجز رُندر»** (`runner_name: ""`) = **بنية تحتية، لا فشل كود**. سجّلها كذلك وأعد المحاولة بدفعة جديدة، ولا تخلطها بفشل حقيقي.
- **لا تفترض أن فشل CI سببه عملك.** سجّل أرقام الالتزام الأساسي قبل أن تبدأ، ثم قارن بعده (جدول «الكناري»).
- **لا تدّعِ نجاحاً لم تتأكّد منه.** إن لم يحصل التشغيل على رُندر، فالحكم «لم يُتحقَّق» لا «ناجح».

### ٩) قواعد فنية تحمي من أخطاء صامتة

- **نهايات الأسطر:** بعض ملفات Dart تستخدم `CRLF`. عدّلها بأدوات تحفظ البايتات وتحقّق بعدّاد قبل وبعد — الخطأ هنا لا يظهر في المراجعة العادية.
- **الأذونات:** السكربت الجديد يحتاج `chmod +x` وإلا فشل صامتاً.
- **بِنايات مطابقة:** `npm ci` و`flutter pub get --enforce-lockfile`.
- **الملفات المولَّدة المتتبَّعة:** شغّل خطوة التوليد وتحقّق أن لا فرق، وإلا انحرف المولَّد عن المصدر بصمت.
- **لا تعتمد على شبكة مساحة العمل:** إن كان `pub.dev` أو `dl.google.com` محجوباً، فالتحليل والاختبار المحليان غير ممكنين — الدليل يُطلب من CI، ولا يُختلق محلياً.
