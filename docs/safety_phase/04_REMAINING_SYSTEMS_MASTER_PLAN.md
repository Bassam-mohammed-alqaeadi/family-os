## ١) الخلاصة للمالك — بلغة بسيطة

### ما الذي اكتشفه الفحص

فحصتُ المستودع كله: **٢٣٣٤ ملفاً، ٩٠٧ وثائق (٥٩٥ منها في الأرشيف)، ١٣٣ شاشة، **٢٥ ملف هجرة مرقّماً حتى ١١٦** (الترقيم يقفز من ٠٠٨ إلى ١٠٠)، ١٩ ملف بيانات وهمية ما زالت تُشحن**.

**ثلاث حقائق كبرى:**

1. **«الدماغ» مبنيّ، و«الجسد» غير مبني.** الخادم يعرف الرياضيات والقوانين والصلاحيات لكل نظام تقريباً (موقع، مناطق، SOS، وقت شاشة، فلترة، مهام، تقويم، دردشة). لكن **الهاتف لا ينفّذ شيئاً**: لا يقيس الاستخدام، لا يحجب تطبيقاً، لا يفلتر موقعاً، ولا يبقى حياً بعد إعادة التشغيل. الكود الأصلي كله **٤ ملفات Kotlin** — كلها للموقع فقط.

2. **لا يوجد «عمود فقري» مشترك.** كل نظام بنى جداوله الخاصة. لا جدول أوامر، لا إيصالات تنفيذ، لا ملف قدرة للجهاز، لا مظروف حدث موحّد (فحصتُ: كلمة `command` تظهر في **صفر** هجرة، و`effective_state` في **صفر**). **هذا بالضبط ما يجعل المنصة تبدو «شاشات منفصلة» لا منصة واحدة.** بناء العمود الفقري مرة واحدة هو ما يوحّدها.

3. **نظام المكافآت مقطوع الرأسين — وقرارك حسمه.** في التطبيق كود «اقتصاد الدقائق» قديم كامل (محافظ لكل تطبيق، قنوات كسب منها `conditionalAppUnlock`) لكنه **يتيم بلا خادم**. وفي الخادم `family_point_ledger` (نقاط) **بلا إنفاق** — والهجرة نفسها تعترف: *«الإنفاق يأتي مع الدقائق»*. **لا جسر بين الاثنين، ولا رابط بأي حجب** (فحصتُ: `screen-time.js` فيه صفر ذكر للنقاط، و`tasks.js` فيه صفر ذكر للحجب). بقرارك «الدقائق هي العملة الوحيدة» صار الطريق واحداً.

### الأحداث الكبرى في هذه الخطة (٦ أحداث)

| # | الحدث الكبير | لماذا هو كبير |
|---|---|---|
| **١** | **بناء العمود الفقري**: قدرة الجهاز + دورة الأمر والإيصال + مظروف الحدث + إصدار السياسة + ناقل تنبيهات واحد | يُبنى مرة، فيستخدمه كل نظام. بدونه كل نظام يخترع تسليمه الخاص (وهذا ما حدث: ٣ آليات تسليم متنافسة — البند C5) |
| **٢** | **اقتصاد الدقائق على الخادم**: دفتر إلحاقي (append-only) + محافظ لكل تطبيق + إنفاق حقيقي + تحويل النقاط القائمة إلى دقائق | يجعل المكافآت **حقيقية**، ويربطها بالحجب والوقت والتعليم في قانون واحد |
| **٣** | **وكيل التنفيذ على الهاتف**: قياس الاستخدام، شاشة الحجب، القفل الفوري، البقاء بعد الإقلاع، الطابور المشفّر | هنا تتحول المنصة من «لوحة تعرض» إلى «أداة تحمي فعلاً» |
| **٤** | **مركز السلامة (Safety Hub)**: الواجهة الأمامية الواحدة للأب — نبض العائلة، طابور الانتباه، بطاقات الأبناء، إجراءات فورية، صحة الحماية | **غير موجود اليوم إطلاقاً** (فحصتُ: صفر ملف). وهو ما يجعل ١٢ نظاماً تبدو كأب واحد |
| **٥** | **موت البيانات الوهمية**: ١٩ ملف mock تُغلق، وأهمها بذرة «ابن ١/ابن ٢» وبذرتا تطبيقات الطفل ومركز التنبيهات المحلي | منصة عالمية لا تُشحن بأطفال وهميين. هذا شرطك الدائم: «بيانات حقيقية فقط» |
| **٦** | **الاختبار الشامل على هاتفين** بمصفوفة حالات × شبكة × إذن × خادم، وبأهداف قياس رقمية | الدليل الوحيد المقبول في العمود الخامس «على الهاتف». CI وحده لا يكفي |

### ما الذي لا نعد به (حدود صادقة، من وثائقك المعتمدة)

- **لا** نقرأ الرسائل، **لا** لقطات شاشة، **لا** صوت محيط، **لا** سجل مكالمات، **لا** إخفاء للتطبيق أو إشعاره. هذه مراقبة لا سلامة.
- **لا** «يحجب كل شيء فوراً»، **لا** «يعرف موقع ابنك دائماً»، **لا** «SOS يضمن استجابة الطوارئ»، **لا** «يكشف كل محاولة تجاوز».
- **لا** تحكم «لا يُكسر»: الطفل يستطيع دائماً سحب الإذن أو حذف التطبيق — **نكتشف ونُبلغ، ولا نعد بالمنع**.
- **سلامة القيادة مؤجّلة** بقرارك. وآيفون مرحلة مستقلة بعد الاختبار الشامل.

## ٣) القرارات المعمارية الكبرى

### ٣٫١ العملة: الدقائق وحدها (قرار المالك 2026-10-11)

**القانون:** الدقيقة هي **وحدة قيمة الوقت الترفيهي** التي يكسبها الطفل وينفقها. لا نقاط ولا XP ولا عملات. كلمة «نقاط/points» في أي عنوان أو ARB قديم = **دين مصطلحات** يُصحَّح، لا عملة منتج.

**ماذا يحدث لـ`family_point_ledger` (خطة من ٤ خطوات، لا هدم):**

| الخطوة | الفعل | لماذا |
|---|---|---|
| ١ | هجرة تنشئ `family_minutes_ledger` + `family_app_wallets` (§٧) | الدفتر الجديد هو الحقيقة |
| ٢ | هجرة تحويل: كل صف `task_confirmed` ⇒ إدخال `credit` بقناة `family_task_child` و`source_type='point_ledger_migration'` و`source_id=` معرّف الصف القديم، **بنسبة ١ نقطة = ١ دقيقة** | النسبة صادقة لأن `family_tasks.points` رقم **حدده الأب نفسه** عند الإنشاء (`CHECK BETWEEN 1 AND 200`)، لا سعر افتراضي خفي |
| ٣ | `tasks.js` وواجهات و٧ تقرأ/تكتب **الدقائق**؛ `family_point_ledger` يصير **للقراءة التاريخية فقط** (لا كتابة جديدة) | لا كسر لرحلة المالك العاملة (شرط §٨) |
| ٤ | بعد تحقق رحلة PostgreSQL أن كل رصيد انتقل: **هجرة ١٢٩** تسقط `family_point_ledger` (في س١٥، أو أبكر بقرار مسجّل) | الإلغاء بدليل، لا بقرار |

**ملاحظة حدودية مهمة:** «محفظة الطفل» المالية (مصروف/ادخار/أهداف) **مستبعدة** صراحة في `01_PLATFORM_SYSTEM_UNIVERSE.md` §٥ كتطوير مستقبلي. محفظة الدقائق **زمن** لا مال — لا خلط.

### ٣٫٢ قانون التجاوز — ماذا تتجاوز الدقائق المكتسبة وماذا لا (من `06_MINUTES_ECONOMY_POLICY.md`)

هذا الجدول **قانون منتج**، يُنفَّذ في الخادم ويُشرح للطفل:

| هل تتجاوز الدقائق المكتسبة…؟ | الجواب |
|---|---|
| القفل الفوري (Instant lock) | **لا** |
| الحجب الدائم (Ruling A) | **لا** |
| وضع نشط بلا استثناء (Smart mode) | **لا** |
| السقف اليومي | **فقط إن** كان الفيضان (overflow) مُفعَّلاً أو المحفظة مستثناة من السقف (Ruling B) |
| نافذة الجدول الصارمة | **قرار مالك** (§١٥ — معلّق) |
| فلتر الويب | **لا** — متعامد تماماً |
| هل يحتاج SOS/الدردشة/القرآن دقائق؟ | **لا** — أسطح معفاة دائماً |

### ٣٫٣ الربط: المكافآت ↔ الحجب ↔ التعليم ↔ SOS

**هذا هو قلب «المنصة الواحدة».** الحوافز الخمسة التي **لا تُكسر** (من `13_CROSS_SYSTEM_DEPENDENCIES.md`):

1. **SOS × القفل/الانتهاء** — الإعفاءات تبقى. سطح SOS لا يُقفل أبداً ولا يحتاج دقائق.
2. **التعليم × الدقائق** — الكسب عبر الدفتر وحده؛ لا نقاط.
3. **فتح فلتر الويب ≠ منح وقت** — متعامدان؛ سماح مؤقت للموقع لا يمسّ المحفظة.
4. **تطبيق مسموح في الوضع الذكي ما زال يحتاج وقتاً متبقياً**.
5. **الذكاء يقترح فقط** — لا منح آلي بلا موافقة أب/أم.

**قنوات الكسب الخمس (E-3، إضافة فقط — `earning_channel.dart` الموجود):**

| القناة | المصدر | الربط بالمنصة الواحدة |
|---|---|---|
| `quranPortion` | ورد القرآن اليومي (FAT-072 ⇄ CHD-025) | التعليم الديني → وقت |
| `athkar` | الأذكار (CHD-027) | القيم → وقت |
| `learningChallenge` | تحدّيات التعلّم (FAT-049 ⇄ CHD-015) | **نظام التعليم (و١٠/و١١ المستقبلي) يغذي السلامة** |
| `familyTaskChild` | مهام العائلة المسندة للطفل (FAT-054/055) | **و٧ المبني فعلاً** → يُحوَّل إلى دقائق |
| **`conditionalAppUnlock`** | **فتح تطبيق مشروط** | **هذا هو رابط الحجب الذي نبّهتَ إليه**: الأب يجعل تطبيقاً «مشروطاً»، والطفل يفتحه بدقائق كسبها |

**قوانين الإسناد (E-4):** الطفل يكسب · الأم **صفر** دقائق (لا تكسب) · الأب ليس جهة كسب.
**سقف الأم (ADR-039):** منح مؤقت ≤ سقف (افتراضي ٣٠ دقيقة)، منفَّذ في `TimeRequestActor.canGrantMinutes`.
**«لا قرارات صامتة»** — هذه تُرفع لك صريحة في §١٥: انتهاء الدقائق المكتسبة · المحفظة الحرة مقابل لكل تطبيق · المنحة إلى المحفظة أم إلى المتبقي اليومي · تجمع الدقائق عبر أجهزة متعددة · هل مكافأة «الانضباط الذاتي» تُعتمد بلا دليل للأب.

## ٤) العمود الفقري المشترك — يُبنى مرة ويخدم كل الأنظمة

**لماذا أولاً:** وثيقة `13_SECURITY_IMPLEMENTATION_SEQUENCE.md` تقول صراحة: *لا تبنِ كل شاشات الأب ثم كل الخادم ثم كل الأصلي — هذا النمط يصنع واجهات كاذبة وإعادة تصميم مكلفة.* وكل شريحة يجب أن تعبر: نية الوصي ← السياسة ← قدرة الجهاز ← التسليم ← الحالة الفعلية ← شرح الطفل ← التنبيه ← التدقيق.

### ٤٫١ ملف قدرة الجهاز — `family_device_capabilities` (هجرة ١١٧)

> المبدأ ٢: **«قدرة الجهاز بيانات»** — التحكم يُقيَّم ضد ملف قدرة مخزّن وحالي، لا يخمنه الواجهة.

```sql
CREATE TABLE family_device_capabilities (
  device_id UUID NOT NULL REFERENCES family_child_devices(id) ON DELETE CASCADE,
  family_id UUID NOT NULL,
  capability_key TEXT NOT NULL CHECK (capability_key IN (
    'usage_metering','app_inventory','app_block_overlay','accessibility_enforcement',
    'instant_lock','web_filter_vpn','background_location','boot_persistence',
    'push_delivery','battery_reporting','tamper_signals')),
  state TEXT NOT NULL CHECK (state IN (
    'confirmed','awaiting_setup','permission_needed','unsupported','revoked','unknown')),
  evidence TEXT NULL,                    -- ما قاله الجهاز فعلاً (لا إحداثيات، لا محتوى)
  app_version TEXT NULL, os_version TEXT NULL,
  confirmed_at TIMESTAMPTZ NULL, reported_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  PRIMARY KEY (device_id, capability_key)
);
```
- **مسار:** `POST /v1/devices/{deviceId}/capabilities` (صلاحية جهاز) — الجهاز **يقرر الحقائق لا السياسات** (المبدأ ٧).
- **قراءة:** `GET /v1/families/{familyId}/children/{childId}/device-capabilities` (وصي).
- **أثر UX:** كل تحكم يعرض `CapabilityHonestyBadge` — «مؤكَّد / ينتظر إعداد / إذن مطلوب / غير مدعوم على هذا الجهاز». **لا toggle مضلّل أبداً.**

### ٤٫٢ دورة الأمر والإيصال — `family_commands` + `family_command_receipts` (هجرة ١١٨)

> المبدأ ٣: **الأوامر غير متزامنة** — معرّف، انتهاء، idempotency، إيصال تسليم، تأكيد حالة فعلية.

```text
دورة الحياة:  accepted → dispatched → received → applied | limited | rejected | expired | failed
```
- `family_commands`: `id, family_id, child_id, device_id, command_type, policy_id, policy_version, payload jsonb, actor_membership_id, idempotency_key UNIQUE, priority, expires_at, state, created_at, dispatched_at, received_at, applied_at`
- `family_command_receipts`: `command_id FK, effective_state jsonb, observed_at_device, received_at_server, receipt_kind ('applied'|'limited'|'failed')`
- **قوانين:** كل إعادة محاولة idempotent · جهاز متأخر **لا ينفّذ أمراً منتهياً** بلا تقييم جديد · الأمر يُقيَّم ضد **القدرة الحالية وإصدار السياسة** قبل التطبيق · **الإلغاء أمر جديد مدقَّق لا حذف تاريخ** · واجهة الأب تعرض الحالة الفعلية لا تفترض أن الإرسال = النجاح.
- **أنواع الأوامر الأولى:** `lock_now` · `release_lock` · `block_app` · `unblock_app` · `apply_time_policy` · `apply_web_policy` · `request_check_in` · `refresh_policy`.

### ٤٫٣ مظروف الحدث الأمني — توسيع `ai_events` لا جدول جديد (هجرة ١١٩)

> المبدأ ٤: **الأحداث حقائق إلحاقية**. والبند C19: اليوم `device.*` فقط.

**القرار: نوسّع `ai_events` ولا ننشئ `security_events` موازياً** — لأن جدولين للأحداث = تكرار من نوع C9.
الأعمدة المضافة: `source_trust ('reported'|'verified'|'inferred'|'unknown')` · `data_quality ('fresh'|'stale'|'partial'|'unavailable')` · `visibility_class` · `retention_class` · `causality_id` · `command_id` · `policy_id` · `severity` · `confidence`.
**عائلات الأحداث المسجّلة:** `time.* app.* web.* place.* sos.* lock.* reward.* device.* check_in.* tamper.*`
**القاعدة R6:** كل حقيقة قابلة للتنبيه تكتب **صفاً واحداً** في `outbox_events` **داخل نفس المعاملة**.

### ٤٫٤ إصدار السياسة — قانون موحّد (المبدأ ٥)

`family_child_screen_time_policies.version` موجود ✅. **يُعمَّم النمط:** كل تغيير محفوظ يحمل المؤلف، اللحظة، النطاق، الإصدار السابق، الإصدار النافذ، وتاريخ الإلغاء.
**قاعدة عملية:** السياسة تُقرأ وتُقيَّم **بإصدارها**، والأمر يحمل `policy_version` — فلا ينفّذ الجهاز سياسة قديمة.

### ٤٫٥ ناقل تنبيهات واحد (R6)

- **عامل outbox داخل العملية**: عند الالتزام + كنس عند الإقلاع + دوري أثناء اليقظة.
- `SELECT … FOR UPDATE SKIP LOCKED` — بلا منافسة بين العمال.
- **مفتاح عدم تكرار لكل (حدث، تسجيل)**.
- **يُهجَّر إليه:** نقرات الدردشة (`family_push_nudges`) **و** تسليمات SOS (`family_sos_alert_deliveries`). **لا جدول نقرات جديد ولا جدول تسليم لكل نطاق.**
- FAT-019 (مركز التنبيهات) يعرض **نفس الأحداث**.

### ٤٫٦ لماذا هذا يجعل المنصة واحدة

| قبل العمود الفقري | بعده |
|---|---|
| كل نظام يخترع تسليمه (٣ آليات — C5) | ناقل واحد، حالة تسليم واحدة في كل الشاشة |
| «تم الحفظ» = ظنّ النجاح | `requested → queued → confirmed → limited → failed` معروضة |
| الواجهة تخمن هل الجهاز يقدر | ملف قدرة يقول، والشارة تشرح |
| كل نطاق له جدول أحداث/تدقيق خاص | مظروف واحد ← تنبيه واحد ← سجل واحد ← تقرير واحد |
| التعليم والسلامة جزيرتان | حدث `reward.approved` يغذي سياسة الوقت بأمر وإيصال |

## ٥) قانون التجربة — UX على مستوى عالمي

**المصدر الملزم:** `07_SECURITY_UX_LOCK.md` (٢٢٠ سطراً) + `18_JACOBS_LAW_AND_EXPERIENCE_CONTINUITY.md`.

### ٥٫١ مركز السلامة = الباب الأمامي للأمن (**غير موجود اليوم — س١٤**)

> *«على الأب ألا يختار بين اثني عشر نظاماً أمنياً قبل أن يفهم حالة العائلة.»*

```text
اليوم (Today)
 └─ مركز السلامة (Safety Hub)
     ├─ نبض سلامة العائلة        «هل العائلة بخير؟»
     ├─ طابور يحتاج قراراً        «ماذا يتطلب قراراً؟»
     ├─ بطاقات الأبناء            «من يحتاج انتباهاً؟»
     ├─ إجراءات فورية             «ماذا أستطيع الآن؟»
     ├─ لقطة الروتين              «أي قواعد نافذة اليوم؟»
     ├─ صحة الحماية               «هل تستطيع المنصة الفعل؟»
     └─ البصيرة والتقرير          «ماذا تغيّر مع الوقت؟»
```

**قانون النبض:** يعرض `stable / needs_review / urgent / unknown` — **ولا يعرض «آمن» أبداً** حين البيانات قديمة أو صحة الحماية معطّلة.
**قانون الطابور:** مرتّب وقابل للتنفيذ: SOS، إصلاح صحة جهاز، طلب، حدث مكان، إجراء منتهي/فاشل، إشارة عالية الثقة.
**قانون الإجراءات:**الإجراء غير المتاح **يشرح لماذا** — لا زر ميت.

### ٥٫٢ نمط «مكتب التحكم الواحد» — لكل تحكم أمني بلا استثناء

```text
عمّاذا يحمي هذا؟
  → من وأي جهاز يشمل؟
  → ما النافذ الآن؟
  → اضبط القاعدة العادية
  → اضبط الجدول / الاستثناءات / تفضيل التنبيه
  → عاين النتيجة واحفظ
  → شاهد التسليم والتاريخ ومسار الإصلاح
```
> *«هذا النمط المشترك هو ما يجعل الوقت والتطبيقات والويب ووضع المدرسة والموقع وصحة الجهاز تبدو منصة واحدة.»*

### ٥٫٣ الحالات السبع لكل لوحة خادم (R4)

`تحميل (AppLoadingState)` · `فراغ (AppEmptyState)` · `غير مُعَد / لا جلسة` · `مرفوض` · `تعذّر الوصول/إعادة محاولة (AppErrorState)` · `قديم (يُظهر الحداثة)` · `جاهز`
**+ `CapabilityHonestyBadge`** على أي شيء لم يؤكده الهاتف.

### ٥٫٤ اللغة البصرية الدلالية (لا لون بلا أيقونة/نص)

| الحالة الدلالية | المعنى | المعالجة البصرية |
|---|---|---|
| علامة/قرار | إجراء عادي للوصي | بنفسجي العلامة — **لا يُستعمل أبداً للإيحاء بالخطر** |
| مؤكَّد/مستقر | قاعدة أو حالة سلامة مؤكدة | نعناعي/أخضر مزرق + نص صريح «مؤكَّد»/«نافذ» |
| يحتاج مراجعة | قرار غير عاجل أو إصلاح | كهرماني + **مقرون دائماً بإجراء تالٍ ملموس** |
| عاجل | انتباه عائلي فوري | مرجاني **باعتدال** + تراتبية إجراء واضحة، بلا تهويل زخرفي |
| مجهول/محدود | المنصة لا تستطيع التأكيد الآن | محايد/رمادي + سبب بلغة بسيطة + إجراء إصلاح/اعرف أكثر |
| معطّل/غير مدعوم | القدرة لا تنطبق على هذا الجهاز/الخطة | باهت + شرح — **ولا toggle مضلّل أبداً** |

### ٥٫٥ قواعد التخطيط والحركة

- الإجراء الأعلى أولوية **بصرياً مفرد** — لا أزرار أولية متنافسة في شاشة.
- بطاقات الأبناء بإيقاع ثابت: **شخص ← حالة ← إجراء تالٍ واحد ذو معنى**.
- الحركة **تؤكد التغيير وتحفظ الاتجاه** — **ولا تخفي أبداً زمن التسليم ولا تتظاهر أن إجراءً بعيداً اكتمل**.
- الأيقونات الاتجاهية تنعكس في RTL · اللون لا يحمل معنى بلا أيقونة/نص.
- نفس بنية المعلومات تخدم الهاتف الصغير والكبير والتابلت وأسطح الويب للأب مستقبلاً.

### ٥٫٦ رحلات الأب الأربع (تُقاس بها كل شاشة)

| الرحلة | المسار | معيار النجاح |
|---|---|---|
| **أ. تفقّد** (يوم عادي) | اليوم ← النبض ← السلامة ← بطاقات الأبناء ← يخرج واثقاً | لا يحتاج فتح تقارير أو إعدادات ليعرف هل الحماية سليمة |
| **ب. توجيه** (إنشاء/تغيير قاعدة) | ملف الطفل ← الوقت/التطبيقات/الويب/روتين المدرسة ← النطاق ← القاعدة ← الجدول/الاستثناءات ← معاينة ← حفظ ← **حالة تسليم صادقة** | القاعدة مفهومة للأب **وقابلة للشرح للطفل قبل التطبيق** |
| **ج. استجابة** (حدث عاجل) | تنبيه ذو معنى ← سياق ← من/ماذا/متى + الثقة/الحالة ← إجراء ← تسليم/إقرار ← مسار تعافٍ أو حل | التنبيه يصنع إجراءً أو حلاً هادئاً — **لا ذعراً ولا طريقاً مسدوداً** |

### ٥٫٧ تجربة الطفل — الكرامة أولاً (الميزة الفارقة رقم ٣)

- الطفل يرى: **القاعدة، السبب، المدة، الأساسيات المستثناة، وحالة طلبه**.
- **لا إذلال، لا لغة مفزعة لإشارات غير مؤكدة، لا تحويل بيانات ناقصة إلى اتهام بسوء سلوك.**
- نبرة الشرح وخيارات الطلب **تتأثر بعمر الطفل ونضجه** — لا تجربة واحدة «تُطفّل» كل الأطفال.
- كل تقييد أساسي له **شرح مفهوم للطفل** و**مسار طلب عادل** حين يناسب.

### س١ — الإشعارات (= ش٤) · **تفتح ٤ أنظمة**

**هدف س١:** إيصال تنبيه سلامة إلى الوصي عند ضغط SOS، أو دخول/خروج الطفل من منطقة آمنة، أو رصد تقرير حماية يحمل إحدى حالات العبث المعروفة. التقارير السليمة أو غير المدعومة لا تُصاغ خطأً على أنها تعطيل للحماية؛ البطارية وطلبات الوقت ليست ضمن الأنواع الأربعة المغلقة في `NOTIFY_TYPES` في س١.

**ما المبني في س١:** الهجرات ١٢٠–١٢٢ (XOR لمالك التسجيل، دليل `delivered` ومحاولات الإرسال، التفضيلات ومفاتيح النسخ) · dispatcher واحد لأحداث السلامة الأربعة · لا يرسل تقرير الحماية إلا للحالات الموجودة في `TAMPER_OBSERVED_STATES` (والـhealthy/unsupported يُسجّلان بلا تنبيه) · FCM HTTP v1 بخيارات أولوية/TTL/قناة · تسجيل الوصي عند إقلاع التطبيق مع كتم الأخطاء · أربع قنوات Android · توجيه Dart آمن إلى FAT-018/014/026.
**ما بقي:** إعداد مفتاح FCM في بيئة التشغيل، واختبار يدوي على هاتفين لسيناريوهات SOS والخروج من المنطقة وتعطيل الحماية تحت DND قبل ش٢. مركز التنبيهات المشترك FAT-019/020 مؤجل لش١٥؛ لا ندّعي نجاح وصول على هاتف من نجاح CI.

**التسليم:**
1. **هجرة ١٢٠:** توسيع `family_push_registrations` **أو** جدول `family_device_push_registrations` بهوية الجهاز (القرار: **توسيع بعمود `device_id NULL` + CHECK «إما عضوية أو جهاز، لا كلاهما ولا neither»** — أقل تكراراً) · **هجرة ١٢١:** إضافة `'delivered'` و`'failed'` إلى `delivery_state` مع قانون: `delivered` يتطلب `delivered_at` ودليلاً من FCM.
2. **عامل outbox داخل العملية (منفّذ):** hook مباشرة بعد COMMIT + `bootSweep` بعد بدء الاستماع للأحداث الأقدم من ٥ ثوانٍ + كنس صغير محدود بعد الاستجابة · `FOR UPDATE SKIP LOCKED` وحدود صريحة · بلا `setInterval` أو مؤقّت دوري · مفتاح عدم تكرار لكل (حدث، تسجيل).
3. **الدردشة وSOS:** يبقى nudger الدردشة وجدول `family_push_nudges` بلا تعديل؛ يصنّف `family.chat_message_sent` كـ`chat_nudge_existing_nudger` لمنع الإرسال المكرر. تسليم SOS يُحدَّث بدليل FCM عبر dispatcher؛ لا يوجد تصعيد SOS آلي ثانٍ في س١.
4. **جمهور س١:** التسجيل الذي يُرسل إليه dispatcher هو تسجيل وصي نشط في الأسرة؛ دعم `device_id` في قيد XOR لا يعني أن مسار تسجيل جهاز الطفل أو تلقيه للتنبيه قد نُفّذ في هذه الشريحة.
5. **تفضيلات لكل ولي — هجرة ١٢٢ (منفّذة):** `family_notification_preferences`؛ أنواع SOS والمناطق والحماية غير قابلة للكتم، وتتجاوز الهدوء و`push_allowed` و`history_only`.
6. **روابط عميقة وقنوات (منفّذة):** FAT-018 لـSOS · FAT-014 للمناطق · FAT-026 للحماية؛ قنوات Android عربية/إنجليزية: SOS/المناطق بصوت عادي عالي الأهمية، الحماية عالية الأهمية بلا صوت، والدردشة تحتفظ بأهمية عادية وصوتها الافتراضي. لا iOS critical alerts.
7. **نقل تسجيل الدفع إلى إقلاع التطبيق (منفّذ):** `MainAppFoundationRuntime` مع كتم فشل Firebase/الإذن/الشبكة؛ يبقى `registerGuardianPush` الحالي في مسار الدردشة كما هو.

**بلا مفتاح FCM:** تُكتب أحداث outbox، ويسجّل dispatcher صراحةً `push_not_configured` ولا يدّعي إرسالاً. مسار تسجيل الدفع يجيب **503 `push_not_configured`** بصدق. مركز التنبيهات داخل التطبيق ما زال ضمن ش١٥؛ لا ندّعي وجود عرض محلي موحّد قبلها.

**قبول:** حدث عبور منطقة ⇒ إشعار للولي على هاتفه ≤ دقيقتين (خادم مستيقظ) · SOS ⇒ إشعار عالي الأولوية · **لا نقرتين مكررتين لحدث واحد** · تسليم يقول `delivered` **فقط بدليل** · تفضيلات الهدوء/القناة لا تكتم أياً من أنواع السلامة الأربعة · الرابط العميق يفتح الشاشة الصحيحة.

### س٢ — متانة هاتف الطفل (= ش٥)

**الهدف بلغة المستخدم:** الهاتف **يبقى يعمل** بعد إعادة التشغيل وتحديث التطبيق وانقطاع الشبكة — ولا يكذب حين يتوقف.

**ما المبني:** `ChildTelemetryService.kt` (٥٢٥) · `LocationSessionCoordinator.kt` (يملك دلالة القطع — LOC-001) · `LocationFixProtocol.kt` (تصنيف صادق) · `WAKE_LOCK` + `FOREGROUND_SERVICE_LOCATION` ✅
**ما الناقص:** `BOOT_COMPLETED` · `MY_PACKAGE_REPLACED` · طابور دون اتصال · تسامح فرق الساعة · إرشاد البطارية · حالة «متوقف» صادقة

**التسليم:**
1. **المانيفست:** `RECEIVE_BOOT_COMPLETED` + مستقبِل `MY_PACKAGE_REPLACED` + `FOREGROUND_SERVICE_SPECIAL_USE` — **بنص إفصاح بارز من ش٢** (شرط Play: الإفصاح قبل الإذن).
2. **إعادة التشغيل:** المستقبِل يبدأ الخدمة **بشرط إذن الخلفية** (أندرويد ١٤+: بدء خدمة موقع أمامية من الخلفية ممكن فقط مع `ACCESS_BACKGROUND_LOCATION`).
3. **الطابور المشفّر المحدود:** تثبيتات غير مُرسلة تُخزَّن مشفّرة **بحدٍّ مقاس** (لا نمو غير محدود)؛ تُرسل بالترتيب عند العودة؛ **الحد يُعلن** في الاختبار.
4. **تسامح فرق الساعة (RESCUE-003):** لا تُرفض نقطة بسبب انحراف ساعة الجهاز؛ `recordedAt` مقابل `received_at` بقاعدة معلنة.
5. **إرشاد البطارية:** كشف استبعاد تحسينات البطارية + توجيه المستخدم — **وبلا ادّعاء** (سياسة Play لـ`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` **غير متحققة بعد** ⇒ **بند بحث قبل التنفيذ** §١٢).
6. **حالة «متوقف» صادقة:** إن توقفت الخدمة (إيقاف قسري، إذن مسحوب) — **الإشعار الدائم يبقى أو يقول «متوقف»**، ولا تتظاهر الخريطة بالحياة.
7. **تمديد المنسّق لا طابور موازٍ** (البند §٥ من خريطة التماسك: «مدّد `LocationSessionCoordinator` بدل إضافة طابور موازٍ»).

**قبول:** إعادة تشغيل ⇒ الخدمة تعود والتثبيتات تُستأنف · تحديث التطبيق ⇒ لا فقد إقران · انقطاع ٣٠ دقيقة ⇒ النقاط تصل بالترتيب · مسحوب الإذن ⇒ حالة «متوقف» صادقة على الطرفين · **فحص هاتف ف٤** يقيس فقد النقاط الفعلي عبر ٢٤ ساعة.

### س١١ — الحد والحجب والقفل الفوري + ربط الدقائق (= ش١٢) ★ **قلب الربط**

**ما يكسره:** **لا مسار طلب وقت بصلاحية جهاز** (الموجود نطاق-عائلة فقط) · CHD-011/FAT-030 يستخدمان كلمة سر مثبّتة (ش١ أخفتها فصارت تجيب `unavailable`) · القفل الفوري موجود خادمياً (`family_child_lock_state`, `insertLock`/`releaseLock`/`readLiveLock`) · **لا تنفيذ على الهاتف**.
**التسليم:**
1. **`POST /v1/devices/{id}/time-requests`** — طلب الوقت **بصلاحية الجهاز** (لا كلمة سر) · **هجرة ١٢٨** تضيف `device_id` إلى `family_child_time_requests` مع قيد «إما عضوية وإما جهاز» + عمود «التطبيق مشروط» في `family_child_app_rules`.

3. **CHD-021 (انتهاء الوقت) و`app_deny_page` يصيران مصدر محتوى الطبقة الأصلية للحجب** · **يُتقاعد مسار `device_lock_service` المحلي**.
4. **التحقق الحقيقي من قفل وضع الطفل** (يحل محل `unavailable` من ش١).
5. **★ الربط بالدقائق (§٣٫٣):**
   - `conditionalAppUnlock`: الأب يجعل تطبيقاً **مشروطاً** ⇒ الطفل يفتحه **بدقائق من محفظته** ⇒ `consume` بقناة `conditional_app_unlock` في نفس معاملة الأمر.

   - **شرح الطفل**: شاشة الحجب تقول **لماذا** (القاعدة + السبب + المدة + الأساسيات المستثناة) و**كيف يطلب** (دقائق أو طلب) — الميزة الفارقة رقم ٣.
6. **تقارير الحماية** ونص اللوحة **«ما أكّده الهاتف»** — لا ما أمر به الأب فقط.

**قبول:** قفل فوري ≤ ٦٠ ثانية على هاتف متصل · تطبيق محجوب **لا يُفتح** بدقائق · تطبيق مشروط **يُفتح** بدقائق ويُنقص المحفظة · منحة مؤقتة **تزيد المتبقي فعلاً** وتنتهي في وقتها · SOS والدردشة والقرآن **تبقى متاحة أثناء القفل** · كل إجراء له إيصال وحالة فعلية.

| الهدف | الرقم |
|---|---|
| الموقع أثناء التنقل | نقطة عمرها ≤ ٥ دقائق عند الوالد في **٩٠٪** من القراءات |
| إشعار الوصول/المغادرة | ≤ **دقيقتين** من وصول النقطة المؤهلة إلى خادم مستيقظ |
| SOS | من الضغطة إلى إشعار الوالد ≤ **٣٠ ثانية** في **٩٥٪** (مدفوعة)؛ المجانية **يُسجَّل الزمن الفعلي** |
| القفل الفوري | ≤ **٦٠ ثانية** على هاتف متصل |
| البطارية | يُقاس على **٢٤ ساعة** ويُعلن؛ المقترح ≤ **٥٪** يومياً |
| الاحتفاظ | لا نقطة أقدم من **٩٠ يوماً ويوم** · الحذف بطلب **فوري في نفس العملية** |
| الدقائق | كسب ← ظهور في المحفظة ≤ دقيقة · إنفاق ← نقصان فوري · **لا رصيد سالب تحت التزامن** |

**شرط التقرير:** **بلا تجميل** — ما فشل يُكتب فاشلاً مع سببه.

## ١١) قواعد التنفيذ الملزمة (لكل شريحة)

**R1 الهوية والأدوار:** معرّفات الخادم فقط · لا كود جديد يقبل معرّف طفل/عائلة غير UUID على مسار خادم · الدور والقدرة على الفعل من **عضوية الخادم ولقطة الصلاحيات** — العميل **يشرح فقط**.
**R2 العقد:** كل مسار: `app.js` ← OpenAPI (حارس الانحراف) ← بانٍ URI في `foundation_gate_configuration.dart` ← دالة في `*_api_client.dart` واحد · مسارات صلاحية الجهاز تُنادى من **Kotlin** مع اختبارات JVM · **Idempotency-Key على كل POST/PUT/PATCH** · الأخطاء بمفردات `HttpError(status, code)` · العميل يترجم **الأكواد لا الرسائل الخام**.
**R3 الشاشات:** **مسار واحد يبنيه الراوتر** يعرض سلطة الخادم · المستودعات المحلية **حقن اختبار/معاينة فقط** · **لا تكديس حقيقة خادم ومحلية في شاشة** · **أعد استعمال معرّفات الشاشات الموجودة قبل إضافة شاشة**.
**R4 الحالات:** الحالات السبع (§٥٫٣) · النص في ARB (العربية أولاً) · التخطيط بـdirectional insets فقط · `CapabilityHonestyBadge` لكل ما لم يؤكده الهاتف.
**R5 ملكية البيانات:** **الخادم يملك الحقائق** · الجهاز يملك فقط **التثبيتات المصفوفة غير المرسلة** · الحالة الزمنية («لا تحديث منذ…») **تُحسب عند القراءة لا بمؤقّتات** (Render ينام) · ثوابت الاحتفاظ في **وحدة خلفية واحدة** وتُعلن في الـAPI.
**R6 التنبيهات:** كل حقيقة قابلة للتنبيه ⇒ **صف `outbox_events` واحد في نفس المعاملة** ⇒ **مُرسِل واحد** (FCM ثم داخل التطبيق) بمفتاح عدم تكرار لكل (حدث، تسجيل) · FAT-019 يعرض نفس الأحداث · **لا جدول نقرات جديد ولا جدول تسليم لكل نطاق**.
**R7 الموافقة والشفافية (مستوى السوق):** إفصاح بارز لمرة واحدة **قبل** طلب الإذن (CHD-003) · إشعار دائم على هاتف الطفل · صفحة «عن الإشراف» في تبويب «أنا» (CHD-010) · **لا إشعارات لكل مشاهدة** · **لا كلمة «صامت» أو «silent»** في أي نص · سجل موافقة خادمي لكل (طفل، قدرة، إصدار نص).
**R8 البوابات:** ترقيم الهجرات تسلسلي من **١١٧** · أي ملف اختبار PostgreSQL جديد **يُضاف إلى سطر `node --test` الصريح في `backend_ci.yml` L85** (وإلا لا تُشغَّل على قاعدة حقيقية أبداً) · تحديث `MOCK_INVENTORY.md` **في نفس الـPR** عند مس أي بذرة · تحديث جدول CURRENT بالأعمدة الخمسة · **بعد أي تعديل على ملف هجرة: أعد حساب sha256 وحدّث `schema-manifest.js`**.
**R9 لغة الدليل:** «على الهاتف» = ✅ **فقط** بفحص جهاز المالك مسجّل في البطاقة · **CI الأخضر لا يُكتب أبداً كتحقق على جهاز**.

**شروط §٨ الثابتة:** العربية أولاً + RTL/LTR والإنجليزية · قارئ الشاشة وأحجام الخط · حالات تحميل/خطأ/انقطاع/فراغ/«غير مُعَد» · **لا رقم بلا مصدر** · **الإحداثيات لا تُكتب في سجلات الخادم أبداً** · لا إخفاء للتطبيق ولا للإشعار الدائم · **لا أسرار ولا معرّفات عائلات في الكود أو CI أو الأدلة** · الخادم وحده يقرر · **رحلات المالك العاملة (تسجيل الدخول، إنشاء عائلة، إضافة طفل) لا تُكسر**.

**تعريف «مكتمل» للمرحلة:** كل نظام من الثمانية **٥/٥** بدليل مكتوب · الموافقة والاحتفاظ والحذف منفّذة ومختبرة ✅ (ش٢/ش٣) · **لا بيانات اصطناعية في release** · الاختبار الشامل منجز وتقريره بلا تجميل · كل حدّ معروف مكتوب في الواجهة ووصف المتجر.

## ١٣) تعليمات الجلسة القادمة — ابدأ من هنا حرفياً

### أول أمر في الجلسة الجديدة
```bash
cd family-os
git fetch origin main && git log --oneline -1 origin/main   # يجب أن يكون b8a33ad أو أحدث
git checkout <فرع الجلسة> && git merge origin/main          # ابدأ من main الأحدث دائماً
```
> **⚠️ لا تدفع أي نسخة قديمة من ش٣ أو من هذه الخطة من أي مساحة عمل سابقة.** النسخة المدموجة في PR #37 هي الأحدث والأصح، وهذه الوثيقة هي المرجع.

### إن كانت هذه الوثيقة غير مدفوعة بعد
أول واجب: **التزمها وادفعها** (`docs/safety_phase/04_REMAINING_SYSTEMS_MASTER_PLAN.md`) في PR مستقل صغير، ثم ابدأ س٠.

### ترتيب العمل
1. **س٠ العمود الفقري** (هجرات ١١٧–١١٩) — **لا تتجاوزه**: كل شريحة تالية تستهلكه.
2. **س١ الإشعارات** (١٢٠–١٢٢) — تفتح ٤ أنظمة.
3. **س٢ المتانة** · ٤. **س٣ اقتصاد الدقائق** (١٢٣–١٢٥) · ثم §٦ بالترتيب.
4. **في نهاية كل شريحة:** البطاقة + `RESUME.md` + `CURRENT_EXECUTION_PLAN.md` + `LOOP_STATE.md` + صف `PHONE_CHECKS.md` إن مسّت الهاتف.
5. **قبل كل دفع:** `cd backend && npm run check && npm test` · `node tools/harness/check_dart_imports.mjs` · `node tools/android/check_manifest_policy.mjs` · `bash tools/harness/harness_check.sh` · `git fetch origin main && git merge origin/main`.
6. **Flutter يُتحقق منه عبر CI فقط** (`flutter analyze --fatal-infos` + `flutter test` كاملاً + بوابة انحراف l10n) — لا Flutter في مساحة العمل.

### قواعد لا تُكسر
- **البيانات حقيقية فقط** — لا mock في تجربة المستخدم (الاختبارات الآلية فقط).
- **الدقائق هي العملة الوحيدة** — لا نقاط.
- **منصة واحدة** — لا نطاق محلي موازٍ لنطاق خادم (C9)؛ الخادم هو الحقيقة.
- **الدفع فوراً** — لا عمل غير مدفوع في نهاية الجلسة.
- **لا ادّعاء بلا إثبات** — قائمة §١ ممنوعة نصاً.
